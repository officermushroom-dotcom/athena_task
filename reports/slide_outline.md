# PoC報告スライド構成

各ページの見出しに結論（メッセージ）を置き、ボディに根拠となる図表・数値を置く。
課題資料の5観点（EDAの示唆／アプローチ／結果／工夫・設計判断／限界と改善方針）に対応させた。
参考資料（スライドの書き方講義）に合わせ、メイン→サブメッセージの章立て、本文16pt相当以上、3色、言葉のかたまりでの改行を守る。

| No. | 章 | メッセージ |
|---:|---|---|
| 1 | 表紙 | 系列2型の設備では誤差を半減でき、急上昇の事前通知にも使える見込み |
| 2 | Ⅰ 結論 | 問い×答え×根拠の縦横表と提案 |
| 3 | Ⅱ 前提 | 精度・頑健性・急上昇・設備差の4つの問いと仮定 |
| 4 | Ⅱ EDA | 油温は直前値でほぼ決まり、負荷との関係は弱い。日周期は系列で3倍異なる |
| 5 | Ⅱ アプローチ | 入力を1つずつ足し、効いたものだけ残した（採否の表） |
| 6 | Ⅱ 評価設計 | 正解時刻で分割、基準は学習期間、通知基準は検証期間で決定 |
| 7 | Ⅲ 結果 | 効果は設備で大きく異なる（系列1は同じ構成でも1〜4%） |
| 8 | Ⅲ 結果 | 負荷・LightGBMは効かなかった |
| 9 | Ⅲ 結果 | 最終テストでMAEが約半分 |
| 10 | Ⅲ 結果 | 夏を含む全月・高温時でも改善 |
| 11 | Ⅲ 結果 | 急上昇時はなお低めに外れ、予測区間からはみ出しやすい |
| 12 | Ⅲ 結果 | 急上昇の8割以上を1時間前に通知できた（誤報は基準次第） |
| 13 | Ⅳ 工夫 | 比較条件の統一と、基準・期間の事前固定 |
| 14 | Ⅳ 限界 | 限界×追加検証の結果×残る課題 |
| 15 | Ⅳ 今後 | 要件確認→事前評価→改善→試行運用と、進む目安 |

## 生成手順

```powershell
python -m athena_task.limits           # 37_limits_checks.json を作成
python -m athena_task.report_figures   # outputs/figures/report_*.png を作成
npm run pdf                            # reports/athena_poc_report.pdf を出力
```

`report_figures` はETTm2の最終テストを再計算し、MAEが `36_ettm2_sixty_minute_final_test.json` と一致しない場合は停止する。
